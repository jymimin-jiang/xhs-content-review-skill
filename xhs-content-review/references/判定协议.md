# 判定协议

每个报告问题应能回答：哪个对象、哪种表达或行为、什么场景、满足哪条条件、证据在哪里、有什么反证。依据不足先记录待确认，不能用模型感觉补成法律结论。

| 情形 | 判定要求 |
|---|---|
| 单词命中 | 先判断行业、产品资格、目的与整句；不直接分级 |
| 禁止条件明确成立 | 必须禁用；注明平台或用户依据，给删除/改写处理 |
| 风险线索明确且有适用依据，仍有条件待确认 | 高危；详细说明不确定性，不以缺证本身证明有害 |
| 只有OCR或必要事实缺失 | 待确认/未检查，不计风险总数 |
| 反例、否定、劝阻 | 不以被引用的词等同宣传；结合整体是否仍推广违规行为 |
| 用户限制比平台严格 | 可启用，但注明用户自定义，不能称官方禁词 |
| 医疗/金融等词 | 个人经历、事实、专业指导和商品推广分开，资格未知不判无资格 |
| 原始规则“建议/避免” | 不自动升级为“必须禁用”；原则性倡议可列提醒 |
| 同一个问题多处出现 | 合并问题，列所有正文和图片位置，不丢掉来源 |
| 同一位置有多个独立问题 | 可分别记录，但不靠来源数量重复统计 |

修改建议须实质消除问题，不改变产品成分、功能、资质或用户经历。必要时删除无依据的主张，只描述已核实事实。不能把病例中的“治疗”改成“调理”以掩盖原宣传行为。无问题不强行改写。“最爱→特别喜欢”等仅可作为真实个人感受的风格选择，不能宣称原词被禁止。

批量稿件逐篇检查，账号资质不能跨账号借用。营销浓度和账号定位属运营建议，背景不足不评判，更无官方百分比阈值。OCR由宿主看图能力完成，脚本不做识别；图像模糊、模型不可看图、路径缺失须如实列未检查。
