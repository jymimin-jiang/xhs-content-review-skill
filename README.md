# xhs-content-review-skill

**发布小红书图文前，让 AI 帮你检查敏感表达、理解使用场景，并把问题、原因和修改建议整理成一份清晰的报告。**

适合个人创作者、品牌内容人员和需要逐篇检查多份稿件的团队。安装完整 Skill 后，在支持该技能的 AI 工具中发送“检查小红书笔记”，提交标题、正文、标签和图片即可开始。

## 能解决哪些问题

- **找出图文中的风险**：同时检查标题、正文、标签和已读取配图，区分笔记文字与图片 OCR，保留图片编号及问题位置。
- **避免只按词语误判**：结合上下文、行业、产品属性、宣传目的与否定/引用语境判断。行业词、疾病名称、普通生活用语不会仅因命中词库就被认定违规。
- **知道为什么、怎么改**：报告区分“必须禁用”和“高危”，说明触发条件与来源，分别给出“建议删除”或“建议改写”。不使用谐音、拆字或 emoji 保留违规意图。
- **保留自己的审查标准**：用户可维护本地敏感词及自定义规则，升级后继续保留这些数据和历史报告。

## 重点检查场景

| 场景 | 检查重点 |
|---|---|
| 个人经历、经验分享、科普讨论 | 真实性、标题与正文一致性、引用和否定语境，避免把正常讨论当成推广 |
| 自有产品推广、品牌合作、商业广告 | 夸大或绝对化宣传、功效承诺、适用资质、广告规则范围 |
| 医疗健康、美妆护肤、食品保健、母婴等行业内容 | 结合行业与产品属性判断功效表达；保留不确定条件，不把资质未知当成无资质 |
| 联系方式、外部平台、资料领取及互动引导 | 结合上下文识别导流、交易或诱导互动；不能只因出现“私信”等词就判违规 |
| 图片中的人物、资料截图、标识和文字 | 可读文字、视觉风险、未成年人及个人隐私；识别不清的区域单独列出 |
| 用户自定义限制 | 明确标为用户规则，与平台依据分别说明 |

当前交付范围是**文字与静态图片**。图片读取取决于宿主模型能力；视频全片检测和账号历史分析尚未实现。批量审查为逐篇独立报告，不操作账号。

## 如何使用

### 1. 安装完整 Skill

仓库中的 `xhs-content-review/` 是完整技能目录。通过目标工具支持的本地技能导入方式安装，保留其 references、assets、scripts 等资源。也可以从发布者提供的正式 ZIP 安装，不需要同时安装仓库副本和 ZIP。

当前版本 **0.5.0**。已完成本地脚本和安装更新机制测试，**尚未完成 WorkBuddy、Codex、Kimi Code 等宿主的安装后端到端验收；豆包直接安装能力尚未确认**。请以所用工具实际支持的能力为准。

详细安装、初始化、升级与回退步骤：[安装更新说明](xhs-content-review/references/安装更新说明.md)。

### 2. 向 AI 提交待检查内容

安装并加载 Skill 后，发送“检查小红书笔记”。AI 会给出可复制模板：

```text
标题：

正文：

话题标签：

图片说明：
（例如：共4张，第1张是封面）

发布场景：
（个人分享／自有产品推广／品牌合作或广告投放／不确定）
```

没有标题可填“暂无”，没有标签可留空；图片在对话中上传。只有文字或图片也能先检查。分多次发送时，最后说“发送完毕”。请自行遮盖不必要的个人信息。

### 3. 查看报告并修改

默认输出离线 HTML 报告，包括原文标红、问题位置、风险等级、详细原因、来源及删除/改写建议。笔记文本、图片 OCR 与画面证据分别展示，信息不足处单列“待确认/未检查”。可使用浏览器打印为 PDF。

报告生成脚本需要 Python 3.9+，使用标准库。宿主不能执行脚本时，可按约定生成等价 HTML；无法写文件时提供文本报告并说明限制。

## 规则与数据来源

- **平台来源材料**：社区规范、社区公约和商业广告规范材料，按照各自适用范围引用；不将旧材料宣称为最新完整官方规则。
- **作者加工数据**：现有965条候选敏感表达由作者收集后二次加工，不代表官方禁词表；词库命中仅作为语义检查线索。
- **用户自定义数据**：本地自行增加或停用的候选词偏好与明确启用的限制，报告标为用户自定义，不伪装成官方规定。停用候选词不豁免适用的平台规则。

来源与边界详见 [来源说明](xhs-content-review/references/来源说明.md)。请尊重作者整理劳动及第三方材料权利；本仓库暂未授予开源许可，不能将可访问等同于可任意转载或再分发。

## 更新与数据保护

- 最新正式包名固定为 `xhs-content-review.zip`，版本归档名如 `xhs-content-review-v0.5.0.zip`，附 SHA-256 校验文件。
- 用户词库、自定义规则与报告保存在 Skill 外；默认用户目录为 `~/.xhs-content-review`，可首次安装时另行指定。
- 升级前备份代码与用户文件；回退只恢复 Skill，保留用户后来新增的数据。
- 旧版包内修改先归档再合并；存在本地内置文件修改时会停止更新，避免直接覆盖。
- 当前采用取得新版包后主动更新。联网版本检查、自动下载与数字签名尚未提供。

更新记录见 [CHANGELOG](xhs-content-review/CHANGELOG.md)。ZIP 是分发形式，实际使用时读取安装后的完整目录。

## 仓库结构与验证

```text
xhs-content-review/     Skill 指令、规则、词库、报告资源和本地更新工具
build_release.py        构建固定包及版本归档
verify_package.py       验证资源引用及报告生成
test_release.py        验证安装、升级、备份和回退
```

运行验证：

```sh
python3 verify_package.py
python3 test_release.py
```

发布者修改规则或代码后，应增加版本号、更新 CHANGELOG，再运行 `python3 build_release.py --version 新版本号`。不要以不同内容覆盖同一版本包。生成 ZIP 后的哈希检查只能验证完整性，不能验证发行者身份。
