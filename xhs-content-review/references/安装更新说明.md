# 安装、更新、备份与回退

此工具只管理本地文件，不联网，不发布内容，不自动安装到任何宿主。需要 Python 3.9+ 与本地文件读写权限。宿主能否加载 Skill、运行脚本和保存文件需分别实测；不承诺所有宿主可直接导入同一 ZIP。

## 文件结构

- Skill 目录：SKILL.md、references/、assets/、scripts/、release.json、CHANGELOG.md。随版本更新。
- 安装记录：Skill 目录中的 installation.json，记录实际数据路径，不放入发布包。
- 用户目录：默认 `~/.xhs-content-review`，可通过 `--data-dir` 指定包外目录。包含用户敏感词.md、用户自定义规则.md、config.json、reports/、backups/。
- 多个安装实例如需不同用户配置，首次安装时指定不同数据目录。共享目录时共享规则与更新锁；备份绑定具体安装位置。

## 首次安装

下载可信来源的 ZIP，解压到临时目录，从临时目录执行管理脚本。所有命令里的 `<...>` 都需要替换成实际绝对路径，不能原样执行。`--target` 必须是最终 Skill 文件夹，不是其父目录。

```sh
python3 "<解压目录>/xhs-content-review/scripts/manage_release.py" install --package "<下载目录>/xhs-content-review.zip" --target "<宿主技能目录>/xhs-content-review" --data-dir "<包外用户数据目录>"
```

脚本不猜测宿主安装路径。安装后按宿主要求重新加载或重启。宿主仅支持手动导入时，也必须把自定义文件放在包外；只复制 ZIP 不会自动执行本工具。

## 更新

先获取新 ZIP，在新解压目录运行脚本；不能从即将被替换的已安装脚本位置运行。`--data-dir` 可省略，沿用目标 installation.json；显式指定不同路径会被拒绝。

```sh
python3 "<新解压目录>/xhs-content-review/scripts/manage_release.py" update --package "<下载目录>/xhs-content-review.zip" --target "<宿主技能目录>/xhs-content-review"
```

更新流程：检查包路径/哈希/数据版本 → 获取更新锁 → 备份 → 检查已安装文件是否改动 → 准备新目录 → 切换版本。用户文件始终留在包外。同版本且内容一致可重复安装；同版本不同内容或直接降级均拒绝。

若发现包内修改，先备份再停止。根据输出或 status 找到备份，比较修改，将用户增补合并到用户目录，再恢复干净的已安装版本后重试。不能直接删除未知文件或强制覆盖。Python 缓存目录不作为用户配置处理。

## 旧版迁移

旧版没有 release.json。初次迁移须追加 `--migrate-legacy`。旧 Skill 整体保存在 `backups/<备份编号>/skill/`；旧 `references/敏感词库.md` 的用户新增区和 `references/用户自定义规则.md` 都在其中。

脚本会在用户目录生成 `迁移待处理-<编号>.json`。让 Agent 对照旧版文件，仅把确认为用户新增或改动的条目合并到包外用户文件，保留明确的启用状态。不要把965条作者候选词整体当作用户规则导入。用户确认合并后把记录状态改为“已合并”，保留记录。迁移未完成时旧设置不会自动生效。

## 状态、手动备份、回退

以下命令也建议使用解压副本中的脚本：

```sh
python3 "<解压目录>/xhs-content-review/scripts/manage_release.py" status --target "<宿主技能目录>/xhs-content-review"
python3 "<解压目录>/xhs-content-review/scripts/manage_release.py" backup --target "<宿主技能目录>/xhs-content-review"
python3 "<解压目录>/xhs-content-review/scripts/manage_release.py" rollback --target "<宿主技能目录>/xhs-content-review" --backup-id "<status列出的备份编号>"
```

回退验证备份完整性和归属，先备份当前版本，再恢复选中 Skill。**不会回退用户词库、配置和报告**。旧版 Skill 若仍读取包内配置，回退到旧版后须按旧版使用方式检查其规则加载情况；包外新增数据仍保留。

每份备份包括 skill/、user-data/ 和 backup.json。用户数据快照可用于人工恢复：先备份现有用户目录，再按文件比较后恢复，避免覆盖升级后新增内容。备份包含用户材料，应按用户本地文件权限妥善保管；本工具不上传。备份不自动清理。

## 故障边界

- 可捕获的版本切换错误会恢复旧目录；损坏的备份拒绝回退。
- 断电、进程强制终止或磁盘故障不保证自动恢复。先确认进程已停止，保存现场的 `.xhs-stage-*` 目录，找到数据目录 backups/ 中完整备份。保留当前内容后移除过期 `.update.lock`，使用 rollback 并显式传入 `--data-dir`；切勿在更新仍运行时移除锁。
- 清单哈希用于检查传输损坏和文件改动，不是发行者身份签名。只使用可信发布渠道的包；当前未提供数字签名。
- 新版 data_schema 不兼容时停止，不自动迁移或修改用户数据。

## 发布者约定

最新固定包名 `xhs-content-review.zip`；版本归档名如 `xhs-content-review-v0.5.0.zip`，每个包同时提供 `.sha256`。release.json 的 files 覆盖全部发布文件（不含它自己），数据版本为1。历史版本包不得覆盖。每次修改先更新 CHANGELOG 和版本，再执行发布工具构建及本地测试。
